## Top structural theme for the autonomy pivot
The approval gates were built as **UI halts that assume a human returns to click**. Two systemic gaps make them misfire under a machine driver:
1. **The scheduler cron is a second, independent publish path** that does not respect the in-flow publisher gate (`hasActiveFlowNodes` ignores `awaiting_approval`, and the post is already `ready`). Any "hold for approval" is defeated whenever `scheduledAt<=now` (#1, #9).
2. **`attachedPost` is snapshotted at run start**, so fresh-goal autonomous runs mis-evaluate cleanlyPostable/needed-assets and PARK instead of publishing (#2, #7).
3. **No reaper / recovery** for `running` runs, `posting` posts, or `running` nodes (#3, #6, #12) — fatal for an always-on autonomous fleet that restarts.

Before flipping Atria to auto-approve: add a first-class autonomous-approval path (not fake `approveNodeId` clicks), re-read the post at the publisher boundary, make `hasActiveFlowNodes` (or the cron claim) respect a parked/awaiting-approval publisher, and add reapers for stuck running/posting states.
