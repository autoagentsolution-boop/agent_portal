## Overview

Add 2 nullable cols to Execution + 1 col to AgentTemplate. Extend `runAgent()` to accept `overrides`, validate against whitelist + schema + size cap, snapshot diff + effective into Execution row. n8n payload contract unchanged (still receives `config` = merged final).

## Key insights

- `validateConfig` util already covers schema check — reuse, don't duplicate
- `agent.configJson` stays untouched (overrides are per-execution only)
- Retry must replay original overrides (= UX of "Run again with these overrides" without modal)
- Audit log already wraps create — extend `afterJson` payload, no new pattern

## Requirements

### Functional
- POST `/api/agents/:id/run` accepts `{ overrides?: Record<string, unknown> }` in body
- Empty/missing `overrides` → behaves identically to current code (no snapshot diff)
- Reject keys ∉ `template.overridableFieldsJson` with 400 + `{ invalid_keys: [...] }`
- Reject if merged config fails `validateConfig` with 400 + field errors
- Reject `JSON.stringify(overrides).length > 16384` with 413
- Snapshot `configOverrideJson` (raw user input) + `effectiveConfigJson` (merged) on Execution
- n8n `payload.config` = effective merged
- Retry endpoint copies `configOverrideJson` from old execution to new execution

### Non-functional
- No data migration on existing rows (cols nullable, default null)
- Backward compatible — no FE/n8n breakage if overrides absent

## Architecture

```
agents.controller.run(id, body)
  └─ agents.service.runAgent(agentId, ws, { triggerType, overrides })
       ├─ validate overrides (overrides-validator.ts)
       │    ├─ keys ⊆ template.overridableFieldsJson
       │    ├─ size ≤ 16KB
       │    └─ effective = {...agent.configJson, ...overrides}
       │       validateConfig(effective, template.configSchemaJson)
       ├─ create Execution { configOverrideJson, effectiveConfigJson }
       ├─ payload.config = effective
       └─ n8n.triggerWorkflow(...)
```

4. **Create `overrides-validator.ts`**
   ```ts
   const MAX_OVERRIDE_SIZE = 16 * 1024;

   export function validateAndMergeOverrides(
     overrides: Record<string, unknown> | undefined,
     baseConfig: Record<string, unknown>,
     overridableFields: string[],
     configSchema: ConfigSchema,
   ): { effective: Record<string, unknown>; snapshot: Record<string, unknown> | null } {
     if (!overrides || Object.keys(overrides).length === 0) {
       return { effective: baseConfig, snapshot: null };
     }
     if (JSON.stringify(overrides).length > MAX_OVERRIDE_SIZE) {
       throw new PayloadTooLargeException('Override JSON exceeds 16KB');
     }
     const allowed = new Set(overridableFields);
     const invalid = Object.keys(overrides).filter((k) => !allowed.has(k));
     if (invalid.length) {
       throw new BadRequestException({ message: 'Override keys not allowed', invalid_keys: invalid });
     }
     const effective = { ...baseConfig, ...overrides };
     const errors = validateConfig(effective, configSchema);
     if (errors.length) {
       throw new BadRequestException({ message: 'Override config invalid', details: errors });
     }
     return { effective, snapshot: overrides };
   }
   ```

5. **Extend `runAgent()` in `agents.service.ts`**
   ```ts
   async runAgent(
     agentId: string,
     workspaceId: string,
     options: { triggerType?: 'manual' | 'retry' | 'schedule'; overrides?: Record<string, unknown> } = {},
   ) {
     // ... load agent + template (existing)
     const { effective, snapshot } = validateAndMergeOverrides(
       options.overrides,
       agent.configJson as Record<string, unknown>,
       agent.template.overridableFieldsJson as string[],
       agent.template.configSchemaJson as ConfigSchema,
     );
     const execution = await this.prisma.execution.create({
       data: {
         // ... existing
         configOverrideJson: snapshot ?? undefined,
         effectiveConfigJson: effective,
       },
     });
     const payload: N8nTriggerPayload = {
       // ... existing
       config: effective,  // ← was agent.configJson
       // ...
     };
     // ... trigger (existing)
   }
   ```

6. **Update `agents.controller.ts` run endpoint**

   async run(@Param('id') id, @Body() body, @Workspace() ws) {
     const dto = RunAgentSchema.parse(body ?? {});

7. **Update `executions.service.retry()`**
   ```ts
   async retry(id: string, workspaceId: string) {
     const old = await this.prisma.execution.findFirst({ where: { id, workspaceId } });
     if (!old) throw new NotFoundException(`Execution ${id} not found`);
     const overrides = (old.configOverrideJson as Record<string, unknown> | null) ?? undefined;
     return this.agents.runAgent(old.agentInstanceId, workspaceId, { triggerType: 'retry', overrides });
   }
   ```

## Success criteria

- `curl -X POST /api/agents/:id/run` (no body) → still works, no snapshot
- `curl -X POST /api/agents/:id/run -d '{"overrides":{"max_items":5}}'` → execution row has `configOverrideJson` + `effectiveConfigJson`
- Invalid key → 400 with `invalid_keys`
- 16.1 KB body → 413
- Retry → new execution has same `configOverrideJson` as old

## Risks

| Risk | Mitigation |
|---|---|
| Existing tests assume payload.config = agent.configJson | Effective = configJson when no overrides → identical behavior |
| Seed re-run wipes manual edits | Seed already idempotent (per memory) |
| Prisma migration on Docker volume | Standard `migrate dev` flow, already used in prior phases |
| `effectiveConfigJson` size unbounded if base config large | Base already validated at agent creation; combined size bounded by schema |

## Security

- Whitelist enforced server-side (FE list = hint only)
- No SQL injection surface (Prisma ORM)
- Audit log entry preserved on every run (existing `callback_received` action)
- 16KB cap prevents DOS via giant JSON
